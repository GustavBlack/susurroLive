# susurroLive v1.9.1 — frameless window per Tech Moca §10.16

**One change after v1.9.0.** The app was already frameless, but its chrome was a local
approximation. v1.9.1 brings it to the house style's frameless-window section exactly: the top bar
is the window's handle, and the document ends with the three window controls at the window's own
top right, above every overlay.

No engine, pipeline, session, import, exporter, LLM-harness or MCP behaviour changed.

## Why

v1.9.0 drew window controls inside the header as 28 px round `icon-btn`s with text glyphs (`–`,
`□`, `✕`). That worked, but it departed from the reference implementation in four ways:

- the buttons sat inside the inset header, not at the window's own top-right corner;
- they were below the dialog backdrop, so a dialog covered them;
- the glyphs were text, not hairline SVG paths on a 10 px grid;
- the middle button swapped text glyphs rather than the hairline restore path.

The Tech Moca guide (§10.16) is the family-wide contract for a window that draws its own chrome.
v1.9.1 follows it.

## What changed

| | v1.9.0 | v1.9.1 |
| --- | --- | --- |
| Bar | `.hdr`, inset 10 px | `.hdr.tm-topbar.tm-titlebar`, full-bleed drag strip |
| Controls | inside `.hdr`, 28 px text-glyph buttons | `tm-window-controls` at the document end, fixed top right, `z-index: 70` |
| Faces | 28 px round `icon-btn` | 26 px round `tm-window-face`, 1 px hairline SVG glyphs |
| State | maximize glyph only | maximize/restore glyph, `aria-label`, `data-maximized`, inactive-window dim |
| Overlays | controls under the backdrop | controls above the dialog backdrop and modals |
| IPC | sender window only | sender window + main frame + renderer URL check |

## Behaviour

- The header is `-webkit-app-region: drag`; buttons, links, inputs, selects, textareas and tabs in
  it are `no-drag`. Dragging moves the window, a drag to a screen edge snaps it, and a double click
  maximises or restores it.
- The three controls are fixed at `top: 0; right: 0`, each `--tm-topbar-h` wide and the bar's full
  height, so the pointer cannot slip past close in a maximised window. The bar reserves
  `calc(var(--tm-topbar-h) * 3 + 8px)` at its right end.
- The visible face is 26 px with a 1 px hairline glyph on a 10 px grid. Hover, close hover, keyboard
  focus and the inactive-window state follow §10.16.
- Main pushes `{ maximized, focused }` on `maximize`, `unmaximize`, `restore`, `focus` and `blur`;
  the renderer asks for the initial state over `window:state`.
- The dimmed ground behind Settings and the session/end dialogs stays draggable; the dialog itself
  is `no-drag`. Toasts are `no-drag`.
- Window IPC acts only on the app's own window, main frame and renderer URL.

## Verified

- `npm run smoke` checks the drag strip, fixed controls at the window's top right, `z-index: 70`,
  26 px faces, three SVG glyphs, and the maximize/restore glyph and `aria-label` following the
  window state.
- `node tools/test-viz.js` (31 checks) and `npm run check:skins` (550 checks) are unchanged and
  green.
- Engine, pipeline, session, import, exporter, LLM-harness, parakeet and MCP suites were not touched.
