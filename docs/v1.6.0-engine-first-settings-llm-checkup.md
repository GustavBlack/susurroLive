# susurroLive v1.6.0

## Engine-first settings

The Settings drawer now leads with the **Engine** select, directly above the model list —
and the model list is scoped to the selected engine:

- **Whisper** → the full ggml catalog (tiny.en … large-v3).
- **Parakeet** → a single model row with provision status; "Set up parakeet…" starts the
  one-time in-app download when the engine is not yet provisioned.

No more wondering why the whisper model list does nothing while Parakeet is active.

## Opt-in AI transcript checkup

A new, strictly opt-in post-transcription step: send a finished transcript to a
user-configured OpenAI-compatible endpoint (LM Studio, Ollama, llama.cpp server, vLLM) and
let a local model fix small ASR errors.

- **Never automatic.** The feature is off by default; the checkup button is invisible until
  you enable it in Settings → AI transcript checkup and configure an endpoint + model.
  Click to run, click again to cancel.
- **Non-destructive by construction.** Words on disk are never mutated. Corrections persist
  as an edit list in the session's `checkup` block and are applied as a read-time
  projection; a per-session **Checked | Original** toggle switches the transcript view and
  every export between corrected and original; **Discard corrections** removes them entirely.
- **Word timestamps untouched** — only one-to-one word substitutions are accepted, so
  karaoke sync and diarize-join stay valid. Edits that would add, remove, or reorder words
  are dropped by the validator.
- **Retranscription-safe.** Each chunk's word fingerprint is stored at checkup time; if a
  chunk is re-transcribed later, its stale edits are dropped (shown drifted) while the rest
  of the session stays corrected. Re-running the checkup regenerates the whole edit list.
- **Vocabulary profiles.** A plain, user-editable `vocabulary.json` in the app data folder
  holds activatable term profiles (a seeded `Default` profile to start). Active terms are
  injected into the correction prompt. Maintain it by hand or with any external tool.
- **Thinking models handled.** Responses are normalized across plain models,
  `reasoning_content` (LM Studio/vLLM style) and literal ` <think> ` thinking blocks —
  see `docs/llm-harness.md` for the full harness contract (the foundation for future
  transcript-AI features).

A running diarizer blocks the checkup (GPU contention); a failed or unavailable diarizer
does not — both diarized and plain transcripts are supported. API-key auth errors surface
as "endpoint requires an API key — enter it in Settings."

## Notes

- **Fixed: the passive update pill never appeared on installed builds.** `updateStatus`
  events carried non-serializable function properties and were silently dropped by IPC
  ("Failed to serialize arguments"); the payload is now clean. Settings → About →
  Check for updates was unaffected.

- Session schema v2 / agent manifest v5 (optional `checkup` block); older app builds
  refuse v2 sessions — update together.
- No new bundled payload: the checkup is HTTP-only and works with any local
  OpenAI-compatible server.
- New tests: `tools/test-llm-harness.js` (9 cases) and `tools/test-checkup-ipc.js`
  (full IPC round-trips incl. drift + export mirroring). New smoke stages assert engine
  ordering and checkup button gating.
