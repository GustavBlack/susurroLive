# v1.5.1 — Record flow, session-folder affordances, new-session attention

Four user-facing changes, one release:

1. **Record button becomes Pause**; END SESSION appears only while paused, behind a
   confirm — kills accidental session ends (test-user report: repeated record presses
   meant "pause" but the first press ended the session).
2. **Right-click context menu** → open the configured Sessions Folder.
3. **Export card gains an "open folder" button** for the session's `exports/` dir.
4. **Guided "New session"**: when record is pressed without a fresh session, the
   modal's New session button shakes once and pulses the theme accent — new users
   can't tell ended from fresh sessions; the needed action lights up.
5. **Record-button morph**: idle circle → rounded square labelled `Pause` while
   recording (replaces the earlier pause-bars idea — the visible state change
   reassures that the session is now in progress). Paused returns to the circle with
   a play triangle.

## UX contract (unchanged actions, new surfaces)

| State            | Record button (left)          | Right slot                      |
|------------------|-------------------------------|---------------------------------|
| idle             | ● circle — start              | *(empty)*                       |
| recording        | rounded square `Pause` — pause| *(empty — no end path visible)* |
| paused           | ● circle + ▸ play — resume    | **END SESSION** (red) → confirm |
| busy (`recordBusy`) | disabled                    | hidden / disabled               |

Confirm copy (verbatim): *"Ending the session cannot be resumed, do you wish to end
the session?"* — **End session** / **Cancel**, `Escape` = Cancel.

## Non-goals

- Recording state machine untouched: `record:start/pause/resume/stop`, `recordState`,
  `Recorder`, pipeline, session schema. Renderer keeps owning every transition.
- No new renderer state fields; `S.recording/paused/recordBusy` suffice. The two
  folder-open features are fire-and-forget IPC, no state.

## 2. `src/renderer/app.js`

- Delete `toggleRecord()`/`togglePause()`; one handler with explicit intents, wrapped
  in `recordAction` so `S.recordBusy` keeps serializing:

```js
const onRecordButton = () => recordAction(() =>
  !S.recording ? startRecording() : S.paused ? resumeRecording() : pauseRecording());
```

  `pauseRecording()`/`resumeRecording()` are the two halves of today's `togglePause()`
  body, unchanged in behavior. `stopRecording()` unchanged.
- End-session flow: `requestEndSession()` (guard `S.recording && S.paused &&
  !S.recordBusy`, show `#endConfirm`, focus `#btnConfirmEnd`), `confirmEndSession()`
  (hide modal → `recordAction(stopRecording)`), `cancelEndSession()` (hide, focus
  back to `#btnRecord`). One `document` keydown: `Escape` hides `#endConfirm`.
- `renderRecordControls()` — single owner of the new surface:
  - record `title`/`aria`: `Start recording` / `Pause recording` / `Resume recording`;
  - `#btnEndSession`: `hidden` unless `S.recording && S.paused`; `disabled = S.recordBusy`;
  - invariant: `#endConfirm` hidden unless `S.recording && S.paused` — the
    `recordState` handler (app.js:1129) already routes through here, so the modal can
    never outlive the paused state;
  - drop every `btnPause` reference.
- Modal close paths: add `closeSessions()` (hide `#sessionModal`, remove `cta` from
  `#btnNewSession`) and route all five `classList.add('hidden')` call sites through it
  (close btn, item open, new-session ok, openDialog ok, import start).
- `openSessions(opts = {})`: `opts.highlight` adds `.cta` to `#btnNewSession`. The two
  guards in `startRecording()` (`!S.session`, `S.session.chunks?.length`) pass
  `{ highlight: true }` — the attention exists only for the record-blocked moment;
  plain `#btnSessions` opens stay quiet. `#btnNewSession.onclick` removes `.cta`
  first so feedback stops the instant the user acts.
- Export folder: in the `[data-export]` wiring block add
  `$('btnExportFolder').onclick` → `api.exportReveal()`; `!res.ok` → `showToast(res.error)`
  (same failure convention as the export buttons — no disabled-state machinery).

## 4. `src/main/index.js` + `src/preload/index.js`

- Add `Menu` to the electron destructure. After window creation:

```js
win.webContents.on('context-menu', () => {
  const dir = settings.get('lastSessionParent');
  Menu.buildFromTemplate([{
    label: 'Open Sessions Folder',
    enabled: !!dir,
    click: () => { if (dir) void shell.openPath(dir); },
  }]).popup({ window: win });
});
```

  One item, cursor-anchored, everywhere; disabled until a sessions folder was chosen.
  No application menu exists today (`autoHideMenuBar`), so nothing to merge with.
- New handler beside `export:run`:

```js
ipcMain.handle('export:reveal', () => {
  if (!active) return { ok: false, error: 'no session' };
  try {
    const dir = path.join(active.folder, 'exports');
    fs.mkdirSync(dir, { recursive: true });       // reveal works before first export
    void shell.openPath(dir);
    return { ok: true, path: dir };
  } catch (err) { return { ok: false, error: String(err.message || err) }; }
});
```

- Preload, export/shell group: `exportReveal: () => ipcRenderer.invoke('export:reveal'),`.

## Edge cases

- **Confirm open, state flips**: overlay blocks other clicks; render invariant hides
  it on any `paused → false` regardless of source.
- **Stop failure**: toast, session stays paused, modal already hidden, END SESSION
  visible again — retry needs no modal resurrection logic.
- **`recordBusy` spam**: `recordAction` serializes; END SESSION disabled while busy.
- **Context menu, no folder chosen**: item disabled, not hidden — the menu itself
  teaches that a sessions folder exists.
- **`export:reveal` before any export**: mkdir-first, so the button always works.
- **Fresh take** (`startRecording` with existing chunks): unchanged toasts; the
  record-guarded modal open now carries `.cta` — desired, that is the confusion case.
