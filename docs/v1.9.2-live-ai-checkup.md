# susurroLive v1.9.2 — live AI checkup

**One change after v1.9.1.** The AI transcript checkup was a post-hoc step: it waited for
recording to stop, every chunk to finish transcribing, and diarization to resolve. But the
chunks that are already transcribed just sit there while the session keeps going. v1.9.2 lets
the checkup run over those words at any time, live — the user gets a clean transcript incrementally
instead of waiting for one correction pass at the end.

No engine, pipeline, recorder, diarizer, exporter or MCP behaviour changed. The checkup block
schema is unchanged: same `edits`, `chunkHashes`, `active` fields, same read-time projection.

## Why

- The words of finished chunks are final ASR output; nothing about them changes while later
  chunks transcribe. Running the correction pass over them early is pure saved time.
- Diarization was never a data dependency of the checkup: edits are word-text replacements,
  speakers join to words at read time. Gating the button on a resolved diarization block made
  the checkup unavailable whenever the diarizer was absent, failed, or simply not wanted.
- Regardless of diarization, the user may need a clean transcript by the end of the session.

## What changed

| | v1.9.1 | v1.9.2 |
| --- | --- | --- |
| Recording | button hidden, run rejected | button visible once words exist, run allowed |
| Chunks in flight | button hidden until the pipeline drains | visible; the run checks what exists at click time |
| Diarization | hidden until the block resolved (done, failed, or unavailable) | irrelevant; hidden only while a diarize run is in flight |
| Settings gate | `llmCheckup` + endpoint + model | unchanged (the only gate) |
| New-chunk safety | not applicable | `applyCheckup` never applies an edit to a chunk the run never saw |
| Imports | decode + transcription both blocked | decode still blocked; transcription may run a live checkup |

## How a live run stays correct

- `runCheckup` snapshots `transcript.words` at call time. `rebuildTranscript` swaps in a fresh
  array on every `chunkDone`, so a run in flight keeps a stable basis: batch ranges, prompts,
  edits and fingerprints all refer to the words that existed when the user clicked.
- Edits are index-based, and appended chunks never shift existing indices (seam dedupe only
  drops words at the new boundary), so edits keep pointing at the same words as the timeline
  grows.
- A chunk re-transcribed during or after the run fails its `chunkHashes` fingerprint and its
  edits are dropped (pre-existing drift machinery, unchanged). A chunk that simply arrived
  later has no fingerprint at all; `applyCheckup` now skips edits whose word's chunk is absent
  from `chunkHashes`, so a coincidental index collision can never apply a correction to a
  chunk the LLM never saw.
- Persistence is unchanged: the finished block is stored in its own session even if the user
  switched away mid-run, stored words on disk are never mutated, and the corrected projection
  arrives over the normal transcript event — corrections appear live while recording continues.

## Behaviour

- The button shows when the feature is configured in Settings (master toggle, endpoint, model)
  and the open session has at least one transcribed word. It appears the moment the first chunk
  lands and stays visible while recording, pausing, and while later chunks transcribe.
- Clicking it mid-session checks the words that exist so far; the button becomes the progress
  affordance (`Processing… n/m`) and a second click cancels, as before.
- A diarize run in flight still holds the checkup off (main enforces it both ways for new runs).
  A checkup already running does not block auto-diarize from firing at stop; the two writes are
  independent blocks (`checkup`, `diarization`) and merge in the same transcript event.
- The Checked/Original toggle, discard, drift toast and exports behave exactly as before.

## Smoke / tests

- Smoke stage 2.8 now asserts the live rules: hidden while the feature is disabled, visible on
  a finished non-diarized fixture, still visible after an in-window diarization, and — the
  regression guard — still visible while a recording status is forced.
- `tools/test-llm-harness.js` case 10 covers the live semantics: the run ignores a transcript
  that grows mid-run, and `applyCheckup` drops edits aimed at unseen chunks.
- `tools/test-checkup-ipc.js` passes unchanged (the IPC contract was already guard-agnostic);
  the removed guards had no dedicated IPC test.
