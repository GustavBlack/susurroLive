# v1.8.0 — Tech Moca redesign: Phase I and Phase II

**Status:** Phase I implemented in v1.8.0. Phase II implemented in v1.9.0.
**Style:** Tech Moca (graphite console, greige ink, condensed chrome), design Gustav Rlo.
**Source of truth:** `D:\ONI_Harness\docs\design\tech-moca\AGENT-BRIEF.md` and `STYLE-GUIDE.md`.

This is a new full version of susurroLive, not a patch release. The layout and the
disposition of the app (header, transport, sources, transcript, visualizer rail, pipeline,
export) stay where they are. What changes is the visual language, the component shapes, the
type system, the status language, and the settings surface.

The work is deliberately split in two phases:

- **Phase I (this release):** one palette, Tech Moca, with every element redesigned to it.
  The 11 existing themes are archived, not deleted. The settings drawer becomes a floating
  window with tabs. The goal is a UI that works flawlessly on its own before any theme
  machinery is layered on top.
- **Phase II (next release):** the archived themes return as **skins** on top of the Tech
  Moca redesign, using their vibrant colours as inspiration. No archived layout, type or
  component language comes back; only colour does.

---

## Phase I — what shipped

### 1. The palette is closed

- `src/renderer/theme/tech-moca.css` is the only token file loaded. It carries the Tech Moca
  dark and light token sets, the type, shape, spacing and motion tokens, and the eight
  session-mark tokens.
- `src/renderer/theme/themes.css` is no longer linked from `index.html`. It stays in the repo
  as the archive for Phase II, together with `themes.js` and `themes.json`.
- `src/renderer/theme/tech-moca.js` carries the canvas palette for the visualizer and the
  speaker-mark order, derived from the same tokens.
- No blue in chrome, links, focus or selection. The only warmth is the sand focus token.
  Accent is off-white, not a hue. Status is always a word on its own well with a line.
- Both modes ship: dark is the default, light is `data-theme-mode="light"`.

### 2. Every element redesigned

- **Header:** Tech Moca top bar. Brand in Saira Condensed caps, session name as an inline
  field, status as a word on a status well with a beacon while recording, quiet icon pills.
- **Transport:** the record control is a pill, not a circle that morphs into a square. It is
  the one primary action on the view. Recording state is carried by the status well and its
  beacon, not by a pulsing ring around the button.
- **Sources:** mono `MIC` / `SYS` labels, a 2 px sand level bar, pill mute/remove actions.
  A muted source is dashed and dimmed, because a muted source is an absence of signal.
- **Transcript:** Inter body at reading size, mono timecodes in the margin, karaoke highlight
  as a selected wash with off-white text. Speaker labels use the eight `--tm-mark-*` tokens,
  because a speaker label is a label, not a status and not a chart series.
- **Visualizer:** retinted to the Tech Moca ramp (accent to surface to text) with the chart
  order for speaker marks (sand, sage, brick, slate, clay, heather). Tiles are flat fills with
  no bloom, no specular lip and no shadow. A 1 px hairline keeps the lattice legible as a
  technical grid. Energy reads through opacity and the ramp, not through glow.
- **Pipeline and export:** chunk chips are small status pills with a worded legend
  (`done / active / failed`), export actions are quiet pills, one primary action stays on the
  record control.
- **Sessions and confirmations:** floating modals with the house modal shadow, a table-like
  session list, and a danger-styled end-session dialog with Cancel focused and the button
  named by its action.
- **Empty and error states:** every gap has a short title and one sentence on what to do.
- **Type:** Saira Condensed 300/500 for display, Inter for body, JetBrains Mono for every
  label, number, path, key and count. Fonts are local woff2 files under
  `src/renderer/fonts/`; nothing is fetched.

### 3. Settings is a floating window with tabs

The old drawer was one long scroll with no grouping. The replacement is a centered floating
window with a backdrop, six tabs, keyboard navigation and a single `Done` action:

| Tab | Contents |
| --- | --- |
| Engine | engine selector, model catalogue and model manager |
| Transcription | language, device, chunk window, VAD, automatic speaker identification |
| Appearance | dark / light mode, palette identity |
| AI checkup | opt-in toggle, endpoint, key, model, context, thinking mode, vocabulary |
| Agents | MCP enable, status, endpoint, copy config, rotate token, reveal file |
| About | version, update check, diagnostics |

Behaviour kept: every control writes through the same IPC calls as before, changes apply
immediately, the vocabulary file is re-read on every open, and the diagnostics block stays
quiet and last. New behaviour: `Escape` closes the window, focus returns to the Settings
button, `Tab` stays inside the window, and arrow keys move between tabs.

### 4. Archive, not deletion

- `themes.js`, `themes.json` and `themes.css` remain the single source of the 11 archived
  palettes. `tools/gen-theme-css.js` still regenerates the CSS and JSON from it.
- The persisted `theme` key in `settings.json` is left untouched. Phase I ignores it; Phase II
  reuses it as the skin id, so a user's old choice is not lost.
- The theme picker is removed from the UI. Appearance offers dark and light only.

### 5. Phase I acceptance criteria

The release is ready for review when all of these are true:

- [x] App boots with 0 page errors in dev and `--smoke`.
- [x] Only Tech Moca tokens are used; no archived palette is loaded.
- [x] No blue in chrome, focus, links or selection.
- [x] One primary action per view (the record pill).
- [x] Buttons are pills; inputs 8 px; cards and modals 10 px; hairlines 1 px.
- [x] Mono for every literal (paths, counts, timecodes, keys, versions).
- [x] Every empty and error state has a title and a sentence.
- [x] Settings opens as a floating window, every tab works, Escape closes it.
- [x] Dark and light both render; focus is sand and visible.
- [x] No horizontal scroll at the minimum window size (680 × 880).
- [x] The visualizer test suite passes with the new palette.
- [x] Smoke covers the floating settings window, tab switching, arrow-key navigation, Escape and
      focus return, mode persistence and the engine-first model list.

### 6. What the reviewer should test

1. Launch, record a short session with a mic, pause, resume, end, and confirm the transcript
   and chunk strip behave as before.
2. Open Settings, visit every tab, change engine, language, chunk window, VAD and the AI
   checkup fields, then close with Escape and with `Done`.
3. Switch to light mode, restart, and confirm the choice persisted.
4. Resize to the minimum window size and check for clipping or horizontal scroll.
5. Open Sessions, import a media file, export `.txt`, `.json` and audio.
6. Run speaker identification on a finished session and check the mark colours.
7. Check the visualizer in idle, capture, paused and import states.

## Phase II — what shipped (v1.9.0)

Phase II is not "bring the old themes back". It is a skin layer: the Tech Moca structure,
type, spacing, shape and interaction language stay fixed; a skin may retint a closed set of
chroma tokens. That is why Phase I had to be stable first: a skin must never be able to move a
layout bound or change a component shape.

### 1. The skin seam

Phase I already separates structure from chroma. Phase II adds one layer above the Tech Moca
tokens:

```css
[data-skin="midnight"][data-theme-mode="dark"] {
  --tm-accent: …;        /* primary pill fill, active underline */
  --tm-accent-strong: …;
  --tm-accent-ink: …;
  --tm-focus: …;         /* focus ring, in-progress, favourite */
  --tm-ok / --tm-warn / --tm-error and their wells;
  --tm-error-strong: …;
  --tm-viz-1 … --tm-viz-6; /* chart and visualizer series */
  --tm-mark-sand … --tm-mark-stone; /* speaker and session labels */
}
[data-skin="midnight"][data-theme-mode="light"] { … }
```

Locked by every skin, never overridden:

- `--tm-bg`, `--tm-bg-alt`, `--tm-bg-raised`, `--tm-bg-sunken`, `--tm-bg-hover`,
  `--tm-accent-wash`
- `--tm-line`, `--tm-line-soft`, `--tm-line-hover`
- `--tm-text`, `--tm-text-dim`, `--tm-text-faint`, `--tm-text-disabled`
- type, spacing, radius, shadow and motion tokens

A skin is a colour story on a graphite floor, not a new theme engine. No gradients, no glow,
no glass, no layout changes.

### 3. Phase II work breakdown

1. **Skin schema.** `src/renderer/theme/skins.js` exports one record per skin with dark and
   light chroma sets, a display name, a source-theme note and a swatch triple. A generator
   (`tools/gen-skin-css.js`) writes `skins.css` and a JSON mirror, the same pattern as the
   archived theme generator.
2. **Contrast gate.** A script checks every skin's accent, focus and status colours against
   the Tech Moca text and floor tokens in both modes, and fails the build below the house
   floors. Blue is allowed only as a skin accent, never as chrome.
3. **Skin picker.** Settings → Appearance gains a skin list with swatches, the current skin
   marked, and a `Tech Moca` entry that means "no skin". The picker is a list of pills, not
   the old grid of mini-palettes.
4. **Swap.** A skin change is a 160 ms fade of the chroma tokens only, no 667 ms cross-fade.
   Reduced motion makes it instant. The visualizer palette and speaker marks follow in the
   same frame.
5. **Persistence and migration.** The existing `theme` key becomes the skin id. Old values
   map one-to-one to the skin ids above; unknown values fall back to `Tech Moca`.
6. **Verification.** Every skin in both modes: no horizontal scroll, focus visible, status
   words legible, one primary action, no blue chrome, visualizer test suite green.
7. **Review.** Smoke captures the skin picker and the `midnight` skin in both modes
   (`native/_smoke_tab_appearance.png`, `_smoke_skin_dark.png`, `_smoke_skin_light.png`);
   a full sheet of every skin is a manual pass.

### 4. Phase II acceptance criteria

- [x] Structure tokens are identical across every skin and both modes.
- [x] Only the chroma set changes; no layout bound moves.
- [x] Every skin passes the contrast gate.
- [x] No skin introduces gradients, glow or glass.
- [x] The skin picker is a tab in the floating settings window, not a second surface.
- [x] Old `theme` values migrate without losing the user's choice.
- [x] The visualizer and speaker marks follow the skin.
- [x] Smoke covers skin persistence and a skin swap in both modes.

**Reviewer pass:** switch through every skin in both modes, restart and confirm the choice persisted,
drag the header, minimize/maximize/restore/close, check the taskbar icon and header mark, and run
`npm run check:skins` plus `node tools/test-viz.js`.

### 5. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| A skin's accent is too dark or too light for the primary pill | Contrast gate plus a per-skin ink token; the gate fails the build |
| Blue creeps into chrome through a skin | Chrome tokens are locked; blue is only allowed in accent, viz and marks |
| The visualizer becomes a glow machine again | Tiles stay flat; only the ramp colours change |
| Old theme ids in settings break the picker | Explicit migration table and a fallback to Tech Moca |
| Phase II tempts a layout change | The skin seam is chroma-only; layout changes need a new phase |

### 6. Out of scope for both phases

- New capture or transcription behaviour; the frameless window added only the `window:*` IPC.
- A custom title bar was out of scope in Phase I. **v1.9.0 exception:** the app is frameless with
  Tech Moca window controls, and the window chrome is part of the design. **v1.9.1:** the chrome was
  brought to Tech Moca §10.16 exactly; see [`v1.9.1-frameless-window.md`](v1.9.1-frameless-window.md).
- `.srt` / `.vtt` export, per-app capture, resident models: still v2.
